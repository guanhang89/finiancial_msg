# bigqmt_converter 完整迁移方案（miniQMT → 大 QMT Redis RPC 桥接）

> 前置阅读：《QMT桥接方案对比分析.md》（选型结论：bigqmt_converter）。
> 本方案基于对本机实际环境的核查结果编写（核查日期：2026-08-08），所有路径均为本机真实路径。

## 0. 现状盘点（已核查）

| 项目 | 现状 |
|---|---|
| 生产 Python 环境 | conda 环境 `kronos-py311`（Python 3.11）：`<项目根目录>\.venv\python.exe` |
| miniQMT xtquant 位置 | `kronos-py311\Lib\site-packages\xtquant\`（常规包，含 `__init__.py`） |
| QMT 终端 | `C:\QMT交易端`（大 QMT，内嵌 Python 3.6 = `bin.x64\pythonw.exe` + python36.dll，**无 python.exe 控制台**） |
| QMT 策略目录 | `C:\QMT交易端\python\`（已存在，内有用户策略文件） |
| QMT 内置 redis 客户端 | ✅ 已内置 `redis 3.5.3`（`bin.x64\Lib\site-packages\redis`），QMT 侧**零额外依赖** |
| 本机 Redis 服务端 | ❌ 未安装（6379 不通），无 Docker —— **需要新装** |
| 生产进程 | `xtquant_tests\unified_trade_monitor.py`（交易主监控：自动交易/盘中止损/网格/ETF轮动/定投）；`scheduled_formula_predict.py` + `agents\liangjia_score.py`（选股打分，用 xtdata 取数） |
| 账户获取方式 | 代码通过 `xt_trader.query_account_infos()` 自动发现资金账号，未硬编码 |
| 在用交易接口 | connect/start/stop/subscribe/register_callback、query_stock_asset/positions/orders/account_infos、order_stock、cancel_order_stock |
| 在用行情接口 | get_full_tick（轮询）、get_market_data（含 `dividend_type='front'`）、download_history_data、get_instrument_detail、get_trading_dates |
| 回调依赖 | `on_stock_order` / `on_stock_trade`（成交回报）；`on_account_status`（仅日志） |

### 目标架构

```
┌────────────────────────── 同一台 Windows 机器 ──────────────────────────┐
│                                                                        │
│  kronos-py311 (py3.11)              Redis 服务         大 QMT 终端  │
│  ┌───────────────────┐        ┌────────────────┐    ┌────────────────┐ │
│  │ unified_trade_    │        │ redis-server   │    │ 策略编辑器运行  │ │
│  │ monitor.py 等旧代码│ RPC    │ 127.0.0.1:6379 │◄──►│ BIGQMT_REDIS_  │ │
│  │ from xtquant ...  │───────►│ db=5           │    │ DRYRUN.py      │ │
│  │        │          │ 请求/响应│  (rpush/blpop) │    │ init/handlebar/│ │
│  │        ▼          │        │  + pub/sub 事件 │    │ adjust 回调泵   │ │
│  │ site-packages\    │◄───────│                │    │ passorder/     │ │
│  │ xtquant (shim) ──►│ 事件推送 │                │    │ get_trade_     │ │
│  │ bigqmt_signal_    │        │                │    │ detail_data    │ │
│  │ trader (兼容层)    │        │                │    │ ContextInfo    │ │
│  └───────────────────┘        └────────────────┘    └────────────────┘ │
│                                                                        │
└────────────────────────────────────────────────────────────────────────┘
```

旧代码 `from xtquant import xtdata/xttrader` **一字不改**：site-packages 里的 miniQMT xtquant 被替换为 bigqmt 的 shim 包，调用经 Redis RPC 转发到大 QMT 进程内执行。

## Phase 0：准备（约 0.5 天）

### 0.1 安装 Redis 服务端（二选一）

**方式 A：Memurai（推荐，原生 Windows 服务）**
1. 下载 Memurai Developer（免费）：https://www.memurai.com/get-memurai
2. 安装后默认为 Windows 服务，监听 6379。
3. 设置密码：编辑 `C:\Program Files\Memurai\memurai.conf`，取消 `requirepass` 注释并设密码，重启服务：
   ```powershell
   Restart-Service Memurai
   ```

**方式 B：tporadowski/redis 移植版（绿色 zip）**
1. 下载 https://github.com/tporadowski/redis/releases 的 `Redis-x64-5.0.14.1.zip`，解压到 `C:\redis`。
2. 编辑 `C:\redis\redis.windows-service.conf`：`requirepass <你的密码>`。
3. 注册为服务并启动：
   ```powershell
   C:\redis\redis-server.exe --service-install C:\redis\redis.windows-service.conf
   C:\redis\redis-server.exe --service-start
   ```

验证：
```powershell
Test-NetConnection 127.0.0.1 -Port 6379   # TcpTestSucceeded = True
```

### 0.2 确认资金账号

打开 QMT 终端登录交易账号，在【交易】页面记下**资金账号**（纯数字串，如 `2220xxxxxx`）。QMT 侧与客户端两份配置里的 `BIGQMT_ACCOUNT_ID` 都用它。

### 0.3 备份

```powershell
# 1. 备份 miniQMT xtquant（回滚用）
Copy-Item -Recurse "<项目根目录>\.venv\Lib\site-packages\xtquant" `
  "<项目根目录>\.venv\Lib\site-packages\xtquant_miniqmt_backup"

# 2. git 提交当前工作区，打一个迁移前标签
cd <项目根目录>
git add -A; git commit -m "chore: bigqmt 迁移前快照"
git tag pre-bigqmt-migration
```

### 0.4 注意：仓库根目录的 `xtquant\` 文件夹

仓库根目录的 `xtquant\`（存放两个开源项目参考代码的目录）与 xtquant 包**同名**。当前不冲突（site-packages 里带 `__init__.py` 的常规包优先于它），但必须遵守一条铁律：

> **任何时候 `kronos-py311\Lib\site-packages\` 下必须存在带 `__init__.py` 的 xtquant 包**（miniQMT 版或 bigqmt shim 版）。否则从仓库根目录运行的脚本会把 `xtquant\` 目录当作命名空间包，`from xtquant import xtdata` 报 ImportError，且报错信息有迷惑性。

建议迁移完成后将该目录改名为 `qmt_bridge_refs\` 彻底消除隐患（本文件随之移动）。

### 1.2 创建 QMT 侧私有配置

在 `C:\QMT交易端\python\` 新建 `bigqmt_signal_trader_local_config.py`，内容（**不要提交到 git**）：

```python
# coding: utf-8
BIGQMT_ACCOUNT_ID = "你的资金账号"     # 0.2 步记下的账号

BIGQMT_REDIS_CONFIG = {
    "host": "127.0.0.1",
    "port": 6379,
    "db": 5,
    "username": "",
    "password": "你的Redis密码",

    # 第一阶段保持 False：只读验证，禁止远程下单
    "rpc_allow_order_methods": False,

    "rpc_process_in_listener": True,
    "rpc_listener_methods": ("*",),
    "rpc_background_threads": False,
    "schedule_adjust": True,
    "schedule_adjust_interval": "500nMilliSecond",

    # 全市场快照缓存：本项目只轮询少量个股，保持关闭
    "full_tick_cache_enabled": False,

    # 大 QMT 终端的 xtdata SDK 无法连接数据服务，下载走终端自身（见 Phase 3）
    "download_jobs_enabled": False,

    # 委托/成交事件推送（on_stock_order/on_stock_trade 需要）
    "exec_events_enabled": True,
}
```

### 1.3 QMT 终端操作步骤（图形界面）

1. **启动大 QMT 终端**（`C:\QMT交易端\bin.x64\XtItClient.exe` 或桌面快捷方式），用交易账号**完整模式登录**（不是极简模式 —— 极简模式是 miniQMT，正是要替换掉的东西）。
2. 确认行情、交易连接正常（右下角连接状态为绿）。
3. 打开【策略研究】/【策略编辑器】（菜单：交易 → 策略交易，或主页面的"模型/策略"入口；不同版本叫法略异）。
4. 在策略编辑器中**打开** `C:\QMT交易端\python\BIGQMT_REDIS_DRYRUN.py`（只加载这一个文件，它会自动 import 其余模块）。
5. 点击【运行】（编译并运行）。
6. **检查输出面板**，出现以下日志即为启动成功：
   ```
   [bigqmt_shell] reload entry paths=['C:\\QMT交易端\\python']
   [bigqmt_shell] local redis config loaded keys=['host', 'port', 'db', ...]
   [bigqmt_shell] local account config loaded=True
   [bigqmt_rpc] transport=redis mode process_in_listener=True ...
   [bigqmt_rpc] started channel=bigqmt:rpc:req:你的资金账号
   [bigqmt_signal_trader] init ok
   ```
7. 如报 `redis config load failed`：检查 1.2 的配置文件名和内容；如报 `import redis failed`：理论上不会（已内置 redis 3.5.3），若出现则把 `kronos-py311\Lib\site-packages\redis` 拷到 `bin.x64\Lib\site-packages\`。
8. **保持 QMT 终端常开**：桥接策略运行在 QMT 进程内，QMT 关闭则桥接中断。后续每个交易日需保证 QMT 在线（可设 QMT 开机自启 + 自动登录）。

> 注意：`BIGQMT_REDIS_DRYRUN.py` 中有一处硬编码 fallback 路径 `C:\QMT交易端\python`（chr 码点拼接，规避 GBK 乱码）。本机 QMT 装在 C 盘且正常从策略目录加载（`__file__` 优先），**无需修改**；仅当你用 exec 方式加载导致 `__file__` 缺失时才需要改成 `C:\QMT交易端\python`。

### 1.4 历史数据下载设置（重要，大 QMT 与 miniQMT 的关键差异）

大 QMT 终端内嵌的 xtdata SDK **不能连接数据服务**，`download_history_data` RPC 默认不可用。历史数据改由 QMT 终端自身下载：

1. QMT 菜单【系统】→【设置】→【行情/数据下载】：开启**登录后自动下载**、**盘后自动补充日线数据**。
2. 首次迁移后手动补一次历史：【数据管理】（或【数据下载】）→ 选择"日线数据"→ 全市场或自选股范围 → 补充最近 2 年。
3. 每日收盘后 QMT 会自动补齐当日数据；`get_market_data` RPC 读的是终端本地已下载的数据，不受影响。

from xtquant.xttrader import XtQuantTrader
from xtquant.xttype import StockAccount
from xtquant import xtconstant, xtdata
import time

trader = XtQuantTrader("", int(time.time()))
trader.start(); trader.connect()

## 日常运维要点

| 事项 | 说明 |
|---|---|
| 每日启动顺序 | ① Redis（Windows 服务自动启动）→ ② 大 QMT 终端登录 → ③ 确认 BIGQMT_REDIS_DRYRUN 策略在运行 → ④ 业务脚本照常 |
| QMT 崩溃/断线 | 重启 QMT 后需在策略编辑器重新运行策略；客户端 RPC 调用会超时（6s）并报错，业务脚本原有重试逻辑可兜底 |
| Redis 故障 | 所有 xtdata/xttrader 调用立即超时失败；Redis 恢复后无需重启 QMT 策略即可恢复 |
| 历史数据缺口 | 发现 `get_market_data` 数据缺日子时，用 QMT【数据管理】手动补充对应品种/区间 |
| 日志位置 | QMT 侧：策略编辑器输出面板；客户端：业务脚本自身日志（unified_trade_monitor.log 等） |
| 升级 bigqmt | 重新执行 Phase 1.1 与 Phase 2.1 的拷贝（覆盖同名文件），QMT 侧重启策略生效 |

## 风险与缓解

| 风险 | 概率 | 缓解 |
|---|---|---|
| QMT 终端未登录/策略未运行导致盘中 RPC 中断 | 中 | 盘前 checklist 确认；monitor 增加 RPC ping 告警（可后续加钉钉通知） |
| `download_history_data` 不可用导致打分数据缺失 | 高（必然） | Phase 3.1 容错 + QMT 自动下载兜底；盘前抽查数据完整性 |
| 前复权字段在大 QMT 返回结构差异 | 低 | Phase 2.3 自检已含前复权断言；不一致时改用 `get_market_data_ex` |
| 下单 RPC 被误开/误用 | 低 | 默认关闭；开启后 `scheduled_tasks_config.json` 的 `trading_enabled` 仍是业务总闸 |
| 大 QMT 部分接口 fallback 数据与 miniQMT 不一致（get_sector_list 等） | 低 | 仅测试脚本用到；生产接口均为原生数据 |
| Redis 密码泄露 | 低 | 两份 config 均不入 git（加入 .gitignore 检查）；Redis 仅监听 127.0.0.1 |

## 回滚方案

任一阶段出问题，回滚到 miniQMT（miniQMT 未被封禁前有效）：

```powershell
$SP = "<项目根目录>\.venv\Lib\site-packages"
Remove-Item -Recurse "$SP\xtquant"
Remove-Item -Recurse "$SP\bigqmt_signal_trader"
Rename-Item "$SP\xtquant_miniqmt_backup" "$SP\xtquant"
git checkout pre-bigqmt-migration -- agents\liangjia_score.py xtquant_tests\utils.py  # 还原代码改动
```
然后停用 QMT 里的 BIGQMT_REDIS_DRYRUN 策略，改用 XtMiniQmt.exe 极简模式登录即可。
