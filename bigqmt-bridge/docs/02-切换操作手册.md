# unified_trade_monitor 切换大 QMT（bigqmt_converter）操作手册

> 整理自 2026-08-09 实际切换过程。环境：正式版 QMT `C:\QMT交易端`（资金账号 <资金账号>），
> 模拟端 `C:\QMT交易端_模拟`（账号 <模拟账号>），Redis 同机 `127.0.0.1:6379 db=5`。
> 方案选型依据见《QMT桥接方案对比分析.md》。

## 0. 架构一句话

策略代码不改 import；通过把 bigqmt_converter 的 `src` 置前，让 `from xtquant import ...` 命中 shim，
所有交易/行情调用转为 Redis RPC，发给大 QMT 策略编辑器里运行的 `BIGQMT_REDIS_DRYRUN` 桥接策略执行。

```
unified_trade_monitor.py
   └─ sys.path.insert(0, bigqmt src)        # shim 接管 xtquant
        └─ Redis RPC (127.0.0.1:6379 db5)
             └─ 大QMT 终端内运行的 BIGQMT_REDIS_DRYRUN 策略 → passorder / ContextInfo
```

## 1. Redis 安装（已完成）

1. 安装 tporadowski/redis 5.0.14.1 MSI（勾选 port 6379 / Add to PATH / Install as Windows Service）。
2. 编辑 `C:\Program Files\Redis\redis.windows-service.conf`：
   ```
   bind 127.0.0.1
   requirepass <密码>
   ```
3. `Restart-Service Redis`，验证：`redis-cli -h 127.0.0.1 -a <密码> -n 5 ping` → PONG。
4. 防火墙不要放行 6379（仅本机）。

**关键约束：客户端 redis-py 必须 < 6**（本环境固定 `redis==5.2.1`）。
redis-py 6+ 默认 RESP3 发 `HELLO` 握手，Redis 5.0 服务端不支持，报 `unknown command HELLO`。
项目 `.venv` 与系统 Python 均已安装 5.2.1，**以后不要升级 redis 包**。

## 2. QMT 侧部署（已完成，正式/模拟两端相同）

### 2.1 拷贝文件到 QMT python 目录

```powershell
$SRC = "<项目根目录>\xtquant\bigqmt_converter-main\src"
$QMT_PY = "C:\QMT交易端\python"   # 模拟端为 C:\QMT交易端_模拟\python

Copy-Item -Recurse "$SRC\bigqmt_signal_trader" "$QMT_PY\bigqmt_signal_trader"
Copy-Item "$SRC\bigqmt_signal_trader_strategy.py" $QMT_PY
Copy-Item "$SRC\bigqmt_signal_trader_redis_rpc_runtime.py" $QMT_PY
Copy-Item "$SRC\BIGQMT_REDIS_DRYRUN.py" $QMT_PY
```

QMT 内置 Python 3.6.8 已自带 redis 3.5.3，QMT 侧无需装任何依赖。

### 2.2 创建 QMT 侧私有配置 `<QMT>\python\bigqmt_signal_trader_local_config.py`

```python
# coding: utf-8
BIGQMT_ACCOUNT_ID = "<资金账号>"   # 模拟端填 <模拟账号>

BIGQMT_REDIS_CONFIG = {
    "host": "127.0.0.1", "port": 6379, "db": 5,
    "username": "", "password": "<Redis密码>",
    "rpc_allow_order_methods": False,    # 上线下单时改 True（见第 6 节）
    "rpc_process_in_listener": True,
    "rpc_listener_methods": ("*",),
    "rpc_background_threads": False,
    "schedule_adjust": True,
    "schedule_adjust_interval": "500nMilliSecond",
    "full_tick_cache_enabled": False,
    "download_jobs_enabled": False,      # 大QMT终端不能下载数据，保持 False
    "exec_events_enabled": True,         # 成交/委托推送，必须 True
}
```

### 2.3 在 QMT 里运行桥接策略

**坑：模型研究的策略列表不是扫描 python 目录**，文件拷进去不会自动出现。必须：

1. XtItClient.exe 正常模式登录（非极简）； XtMiniQmt 与 XtItClient 不要同时登同一账号
2. 「模型研究」→「+新建策略」→ 类型 **python** → 名称用纯 ASCII：`BIGQMT_REDIS_DRYRUN`
3. 删除模板内容，用记事本打开 `python\BIGQMT_REDIS_DRYRUN.py`（GBK 编码），全选粘贴进编辑器
   （文件内容本身全 ASCII，粘贴不会乱码；**不要用外部编辑器把它另存为 UTF-8**）
4. 右侧设置：运行周期 `1分钟`；标的 `000300.SH`；不勾「启动本地python」；不开自动交易
5. 保存 → 编译 → 运行
6. 输出面板出现 `started channel=bigqmt:rpc:req:{账号}` 即就绪
7. 改配置后需停止再运行策略；reload 不生效就重启终端

## 4. unified_trade_monitor.py 代码改动（已完成，共 4 处）

| 位置 | 改动 | 原因 |
|---|---|---|
| 25 行 | 删 `os.environ['PATH'] = ...bin.x64...`，改为 `sys.path.insert(0, r"...bigqmt_converter-main\src")` | RPC 模式不需要 miniQMT DLL；内置 sys.path 使 shim 命中不依赖外部 PYTHONPATH |
| 63 行 | `QMT_USERDATA = ''` | shim 的 XtQuantTrader 忽略 path/session_id，占位防误导 |
| 主循环断线检查（~4894） | `on_disconnected` 不触发，改为探活式：每轮 `query_stock_asset(acc)`，异常即置 `disconnected[0]=True` 走原重连逻辑 | shim 无断线推送 |
| 连接失败钉钉文案（~2998） | 改为提示检查大QMT终端/桥接策略/Redis | 原文案指向 MiniQMT |

不需要改：所有 `query_*` / `order_stock` / `cancel_order_stock` / `get_full_tick` / `get_market_data` 调用、
回调注册、`connect()` 返回码判断（shim 失败抛异常，被现有 try/except 捕获，行为等价）。

## 5. shim 层兼容性修复（已完成，`src\xtquant\xtdata.py`，对业务透明）

实测中发现大 QMT 桥与 miniQMT 的 3 个数据格式/行为差异，已在 shim 内消化：

1. **长表转置**：桥的 `get_market_data` 返回长表 DataFrame（columns=index/open/close/...），
   shim 归一化为 miniQMT 原生 `{field: DataFrame(index=代码, columns=时间)}`，时间标签纯数字化
   （`20260807 14:56:00` → `20260807145600`，兼容 monitor 的 `pd.to_datetime(format='%Y%m%d%H%M%S')`）
2. **多股批量拆分**：大 QMT 多股 `get_market_data` 返回异常结构 `{'is_copy': None}`，
   shim 自动逐股查询再按 field 纵向拼接
3. **`time` 字段 + 空起始时间**：
   - 大 QMT 不支持 `time` 字段 → RPC 前剥离，返回时按 miniQMT 惯例合成（epoch 毫秒）
   - 账号 1m 数据权限限最近一年（20250809 起），`start_time=''` 被服务端当"从头开始"会拒绝
     （报"超出最大起始时间" 数据类型 3001）→ shim 按 `count`×周期推算起始时间
     （1m 按 240 根/天 ×2.2 +7 天，封顶 360 天；已实测 count 语义=区间内最新 N 根，结果等价）

## 6. 上线切换步骤（待执行）

前置状态：正式版桥已运行、只读链路全部验证通过、`rpc_allow_order_methods=False`。

   `"rpc_allow_order_methods": True` → QMT 策略编辑器停止 BIGQMT_REDIS_DRYRUN 再运行
   （开后 `price_type=FIX_PRICE` 才透传到 passorder）
3. **小额实盘验证**（交易日盘中）：
   - 100 股买单：确认委托/成交钉钉通知、`on_stock_order`/`on_stock_trade` 事件到达、
     `query_stock_orders` 状态流转 48→50→56、`_pending_orders` 正确 resolve
   - 一笔卖出 + 一笔撤单
4. **持续观察 1-2 天**后转正式运行。盯日志：
   - `[盘中止损] 无数据` 应随盘中 1m bar 累积消失（9:31 起）
   - `[止损] 跳过: 指标计算失败` 不应频繁出现
   - `[QMT] RPC 探活失败` 出现 → 检查 QMT 终端/桥接策略/Redis

## 8. 已知缺口（接受现状）

| 缺口 | 影响 | 兜底 |
|---|---|---|
| `on_order_error` 不推送 | 废单回滚不由回调触发 | `_check_stale_orders` 60s 轮询终态处理 |
| `on_disconnected` 不触发 | 无断线推送 | 探活式重连（第 4 节改动） |
| `on_account_status` 不推送 | 仅少一条日志 | 无 |
| `download_history_data` 空操作 | 无法主动补历史数据 | 终端按需向数据服务拉取（已验证 1m/1d 可查，1m 限近一年） |
| 首次重 RPC 冷启动 >6s | 偶发超时 | 客户端超时已 15s，热身后 ~0.5s |
| RPC p50≈13ms | 对 5s 级扫描周期无影响 | — |
